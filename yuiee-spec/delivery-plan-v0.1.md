## 1. 阶段与退出条件

| 阶段 | 工作内容 | 可审查产物 | 退出条件 |
|---|---|---|---|
| A. 基础与协作（第 1～6 周） | TypeScript、React、Electron 入门；内存事项列表；分支与 PR 练习 | 小练习、运行说明、双方 PR 和评审记录 | 两人均能独立完成小需求、验证、提交和评审。 |
| B. 需求与设计（第 7～10 周） | 复核需求、用户故事、原型、最小版本边界 | 产品目标、原型、验收清单、架构评审记录 | 双方对做什么、不做什么、如何验收达成一致。 |
| C. 最小交付（第 3～4 个月） | 手动录入、SQLite、编辑删除、测试、CI、安装包 | v0.1 学习增量、README、测试与安装记录 | 开发版及安装版可持久化数据，另一台电脑可按文档使用。 |
| D. 业务可靠性（第 5～6 个月） | 假数据候选项、草稿、排程、版本、事务、幂等；逐步补齐周/日视图 | v0.2 学习增量、状态图、单元与集成测试 | 预览不写正式日程；旧版本、重复确认、冲突和失败事务均有验证。 |
| E. AI 与异常（第 7～8 个月） | 文字提取、图片粘贴、流式回复、澄清、Key 安全 | v0.3 学习增量、假 API 测试、授权实测记录 | 用户可完成截图到日历路径；断流和失败不污染日历，他人事项不自动纳入。 |
| F. 长期运行（第 9～10 个月） | 通知、托盘、自启动、悬浮窗、恢复、迁移与日志 | Windows 验收记录、备份恢复说明、候选发布版本 | 安装版在真实登录会话中通过后台提醒、重启、休眠唤醒和升级验证。 |
| G. 试用与维护（第 11～12 个月） | 小范围试用、缺陷修复、安全回归、正式发布与复盘 | 第一版安装包、发布记录、需求验收矩阵、复盘 | 阻断发布及严重缺陷关闭，最终需求全部有验收证据，能维护已发布版本。 |

月份是容量估算，不是硬性截止日；默认每人每周约 8～10 小时，投入较少可延长至 12～18 个月。第 9～10 周与第 3 个月有时间重叠，按阶段先后推进，不要求并行赶工。每阶段在同一 Git 仓库留存代码与文档；变更通过分支和评审进入主分支。若退出条件失败，先修复或调整计划，不跳过验证。具体任务、轮岗及第一周安排见执行主线。

## 2. 需求追踪矩阵

| 需求 | 设计模块 | 核心验证 |
|---|---|---|
| FR-01、FR-02 | 对话 UI、粘贴输入 | 截图预览、移除、纯文字与图文发送。 |

| FR-09 | 日/周日历、事项服务 | 查看、编辑、删除和重启保留。 |
| FR-10 | 提醒服务、Windows 通知 | 1 天/1 小时提醒、编辑取消、重启和错过提醒。 |

| FR-13 | 事项分类和确认服务 | 普通事项未确认前无提醒。 |
| FR-14 | Key 存储与设置 | 未配置、更新、屏蔽回显、日志检查。 |
| FR-15 | 统一错误状态、冲突处理 | 网络故障、无空位、时间含糊均不误写。 |

## 3. 工程约定

1. `main` 保持可构建；功能分支以 `codex/` 为前缀。小步提交，关联需求 ID 或学习任务编号；一人开发，另一人评审。双方按阶段轮换职责，避免长期只熟悉界面或数据库。
2. TypeScript 严格模式；共享输入输出类型与运行时校验并存，避免仅靠编译期类型信任模型或 IPC 数据。
3. 数据库迁移只向前运行，修改数据前先备份测试样本；为关键事务写回滚测试。
4. AI 适配器可注入假实现，自动测试不依赖真实 Key 或外部网络；仅发布前做一次授权的真实 API 端到端验证。
5. 代码检查、类型检查、自动化测试、构建纳入 CI；安装包和系统通知另在 Windows 人工验收。
6. 任何截图、Key、完整 API 请求不得进入 Git、测试快照或日志。

## 4. 第一版完成定义

- 需求矩阵 FR-01 至 FR-15 均有对应实现和验收证据。
- 从真实截图粘贴到最终确认、日历显示、到期提醒的主流程可重复完成。
- 不明确的事项不被自动保存；他人的事项不产生提醒；无空位不强行安排。
- 应用关闭主窗口后提醒仍可运行；用户显式退出和关闭开机启动的行为一致。
- 安装包能在目标 Windows 环境安装、启动、卸载；数据位置与删除方法写入 README。
- 交付测试结果、已知限制和后续版本候选事项。
