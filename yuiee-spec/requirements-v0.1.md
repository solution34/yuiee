## 1. 产品目标

Yuiee 是面向个人使用的 Windows 本地日程助手。用户可从 QQ、微信等应用截图，将图片通过 `Ctrl+V` 粘贴到 Yuiee 的对话框，补充文字说明（例如可用时间段、截止时间、预计耗时），由 GPT 提取待办和时间信息。用户核对并确认后，系统自动将事项安排到应用内日历。

第一版的成功标准：用户能从一张含有任务信息的截图出发，完成「粘贴—补充说明—识别—确认—自动排程—在日历中查看或修改」的完整流程；关键信息不明确或排程失败时，不生成未经用户确认的日程。

## 2. 范围

### 第一版包含

1. Windows 本地应用；应用内对话框支持图片粘贴和文字输入。
2. 调用用户配置的 OpenAI API Key，分析图片和文字，提取一个或多个事项。
3. 显示结构化识别结果，允许用户修改、删除、补充后确认。
4. 自动排程到应用内日历，提供日、周、月视图中的至少一种日历视图，以及事项详情、编辑、删除。
5. 本地持久化保存事项、日程和必要的用户设置。
6. 对输入、网络、API 和排程异常给出可理解的提示。

### 第一版不包含

1. 应用自带截图快捷键；截图由操作系统或其他应用完成后粘贴。
2. 与 Google、Outlook、微信、QQ 或系统日历同步。
3. 手机端、多用户协作、云端账户与跨设备同步。
4. 在用户确认识别结果前自动写入日历。

## 3. 核心流程

1. 用户在其他应用截图并复制到剪贴板。
2. 用户打开 Yuiee 对话框，以 `Ctrl+V` 粘贴图片，可输入补充说明并发送。
3. Yuiee 展示处理中状态，并调用 GPT 提取标题、类型、日期、时间段、截止时间、预计耗时和需澄清的问题。
4. Yuiee 显示每个事项及其来源信息。用户可逐项编辑、删除或确认。
5. 用户确认后，Yuiee 根据已存在日程和排程规则自动安排。
6. Yuiee 展示安排结果；若信息不足或没有可用时段，列出原因并要求用户处理。
7. 用户可在日历中查看、编辑或删除事项。

## 4. 功能需求与验收标准

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-01 | 对话框接收剪贴板图片 | 复制截图后，在对话框按 `Ctrl+V` 可见图片预览；可移除并重新粘贴。 |
| FR-02 | 对话框接收文字说明 | 可单独发送文字，或把文字与图片一起发送；空内容不可发送。 |
| FR-03 | GPT 提取事项 | 对包含多个事项的输入，结果以多条独立事项展示；无法确定的信息标记为待确认，不凭空补全。 |
| FR-04 | 用户确认识别结果 | 每条事项可编辑标题、日期/截止时间、时间约束和预计耗时；可删除；确认前不进入日历。 |
| FR-05 | 自动排程 | 确认后在可安排时段内寻找不与现有事项冲突的空位；成功时生成日历事项并展示安排时间。 |
| FR-06 | 排程失败处理 | 截止时间不明确、无可用空位或与固定日程冲突时，明确提示原因，不强行安排或产生重叠事项。 |
| FR-07 | 应用内日历 | 可按日期查看已排事项；可打开详情、编辑和删除；重启应用后仍可查看。 |
| FR-08 | API Key 配置 | 用户可在应用中配置自己的 Key；未配置时提示并阻止 GPT 请求；界面不明文回显完整 Key。 |
| FR-09 | 异常恢复 | 网络/API 失败时保留当前输入和图片，可重试；失败请求不得产生重复日程。 |

## 5. 第一版排程规则（待基线确认）

1. 使用用户本机时区；默认每日可安排时段为 **09:00–22:00**，包含周末。
2. 未填写预计耗时时，默认 **30 分钟**。
3. 有明确开始和结束时间的事项视为固定日程。若与已有日程冲突，提示用户处理。
4. 有明确截止时间、但无固定开始时间的任务，在当前时间之后、截止时间之前寻找最早的完整空闲时段。
5. 用户指定可用时间段时，仅在该时间段与默认可安排时段的交集内安排。
6. 截止时间或日期含糊、没有完整空位、或存在冲突时，保持事项为待处理状态，提示用户修改；不得越过截止时间、扩展可安排时段或重叠排程。
7. 一次确认产生多个任务时，先按截止时间从早到晚安排；每安排一项就更新可用空位。相同截止时间保留识别结果中的顺序。
8. 自动排程结果必须可手动编辑；编辑时继续检查时间冲突。

## 6. 数据与隐私要求

1. 日程和设置保存在本机；第一版不建立 Yuiee 云端账户。
2. 用户发起识别时，所选图片和文字会发送至 OpenAI API；发送前应在界面说明这一点。
3. API Key 不写入仓库、日志或导出文件；本地存储方案在架构设计阶段确定。
4. 日志不记录截图原文、完整 API Key 或完整请求载荷。
5. 用户可删除本地日程；图片是否需要长期保存，应在设计阶段明确，默认仅为识别过程临时使用。

## 7. 质量要求

1. 关键流程有自动化测试：事项校验、排程边界、冲突检测、持久化与 API 失败处理。
2. 对 GPT 的结构化输出进行校验；无效或缺失字段不得直接进入排程。
3. 本地启动、构建、测试命令和环境变量在 README 中有可重复的说明。
4. 提供可运行的第一版交付物及手工验收记录；发布前验证全流程。

## 8. 待确认事项

1. 固定时间事项与有截止时间的任务的上述区分，是否符合预期。
2. 日历最低需要日视图、周视图还是月视图；暂按周视图设计。
3. 是否需要第一版就支持系统通知/提醒；当前范围未包含提醒。
4. 同一条截图中若包含他人的安排，是否只提取用户明确要求记录的事项；暂按此原则处理。
