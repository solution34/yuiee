## 1. 产品目标

Yuiee 是个人使用的 Windows 截止时间助手。用户从 QQ、微信等应用截图，以 `Ctrl+V` 粘贴到 Yuiee 对话框，并补充文字。应用调用 GPT，逐步显示可读的分析结果，识别**只属于用户自己的事项**及其截止时间。应用先生成模拟日程与提醒方案，允许用户继续对话修改；用户最终确认后，才写入本地日历并启用提醒。

产品重点是避免遗漏截止时间。普通日常事项不是默认提醒对象：AI 可建议记录或提醒，但必须先交由用户确认。

第一版成功标准：用户能够完成「粘贴截图和说明 → 看到流式回复 → 核对属于自己的事项 → 查看模拟安排 → 对话修改 → 最终确认 → 日历查看 → 截止时间提醒」的闭环。

## 2. 第一版范围

### 包含

1. Windows 本地应用；对话框支持图片粘贴、文字输入和多轮对话。
2. 使用用户提供的 OpenAI API Key，对图片及文字进行事项提取，并以流式文本回复展示处理结果。
3. 识别并筛选用户自己的事项；对于归属、日期或内容不确定的信息，向用户提问，不自动纳入日程。
4. 生成**模拟安排**：展示识别事项、拟定日历时间、提醒时间与冲突情况；模拟结果不会写入正式日历。
5. 用户可通过继续对话或编辑字段调整模拟安排；经最终确认后才保存正式日程和提醒。
6. 应用内日视图和周视图；周视图为主要入口，日视图可查看当天详情。
7. 截止时间提醒：默认提前 1 天和 1 小时，通过 Windows 系统通知及应用内提示呈现；每项可修改提醒时间。
8. 默认开机自启动，用户可在设置中关闭；应用提供可移动的桌面悬浮小窗，展示临近截止时间的简短提示，可隐藏或关闭。
9. 本地保存事项、日程和设置；支持查看、编辑、删除。

### 不包含

1. 应用自带截图快捷键；截图由操作系统或其他应用完成后粘贴。
2. 与第三方、系统日历同步；手机端、多人协作、云账户与跨设备同步。
3. 未经用户最终确认，自动创建正式日程或启用提醒。
4. 对他人的事项创建日程或提醒。

## 3. 核心业务流程

1. 用户复制截图，在 Yuiee 对话框按 `Ctrl+V` 粘贴；可同时输入说明。
2. 用户发送后，界面逐步显示 GPT 的可读回复，并明确区分「待确认的提取结果」与最终日程。
3. Yuiee 只保留可能属于用户自己的事项。归属不清、截止时间不明或只有日期没有具体时刻时，要求用户确认或补充。
4. Yuiee 在不改变正式日历的前提下计算模拟安排，列出事项、拟定时间、默认或自定义提醒、冲突和未安排原因。
5. 用户继续对话提出修改，例如更改截止时间、预计耗时、可用时间段、是否提醒。Yuiee 更新模拟安排。
6. 用户明确进行最终确认。Yuiee 再次校验模拟安排，然后一次性保存成功的事项；有冲突或缺失信息的事项仍待处理，不偷偷写入。
7. 用户在日历、系统通知和桌面悬浮小窗中查看近期截止时间；可修改或删除事项。

## 4. 功能需求与验收标准

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-01 | 剪贴板图片 | 复制截图并在输入区按 `Ctrl+V`，显示预览；可移除和重贴。 |
| FR-02 | 文字与对话 | 可发送纯文字，或同时发送图片与文字；空内容不可发送；可基于上一轮结果继续对话修改。 |
| FR-03 | 流式回复 | 发送后回复逐步呈现；处理中、完成、失败状态可区分；中途失败保留已输入内容并允许重试。 |
| FR-04 | 个人事项筛选 | 含有他人任务的截图不得直接为他人创建事项；归属不确定时显示待确认问题。 |
| FR-05 | 事项提取 | 能将多个个人事项拆为多条，分别显示标题、截止时间、预计耗时、约束和不确定字段；不能根据截图猜测缺失时刻。 |
| FR-06 | 模拟安排 | 正式保存前可见拟定日历时间、提醒时间、冲突和未安排原因；此时日历数据库中不存在这些新事项。 |
| FR-07 | 多轮修改 | 用户在对话中更改事项或安排后，模拟结果相应更新；旧模拟方案失效，避免误确认。 |
| FR-08 | 最终确认 | 只有用户明确确认当前模拟方案后才保存；重复点击或请求重试不得创建重复事项。 |
| FR-09 | 日历 | 周视图为主要入口，可切换日视图；可查看、编辑、删除个人事项；重启后数据保留。 |
| FR-10 | 截止提醒 | 有确定截止时刻的事项默认在提前 1 天及 1 小时触发提醒；可逐项编辑；重启后提醒仍有效。 |
| FR-11 | 开机启动 | 默认随用户登录 Windows 启动；设置中可关闭或重新开启，状态与实际启动配置一致。 |
| FR-12 | 桌面悬浮提示 | 可移动的小窗显示最近的截止事项及剩余时间；可隐藏、重新显示；不会阻止主应用正常使用。 |
| FR-13 | 普通日常事项 | AI 可建议记录或提醒普通事项，但不得自动启用提醒；由用户确认后才保存。 |
| FR-14 | API Key | 未配置 Key 时引导配置；设置界面不明文回显完整 Key；Key 不进入仓库或日志。 |
| FR-15 | 异常与冲突 | 网络/API 失败、时间含糊、无可用时段或日程冲突时说明原因，不产生重叠或未经确认的日程。 |

## 5. 时间与提醒规则

1. 使用用户本机时区。默认可安排时段为每日 **09:00–22:00**，包含周末；该时段只用于提出模拟安排，不限制截止提醒时刻。
2. 没有预计耗时的事项，模拟安排默认按 **30 分钟**计算。
3. 有确定截止时刻但无固定执行时间的任务，在当前时间之后、截止时刻之前寻找最早的完整空位；用户给出可用时间段时，仅在其与默认时段的交集内安排。
4. 截图只有截止日期、没有具体时刻时，**每次询问用户**，不默认填入 18:00 或 22:00。
5. 有明确开始和结束时刻的事项先作为固定时间建议呈现。若其主要意义是提醒截止时间，用户可在模拟方案中改为截止任务；不擅自转换类型。
6. 多事项按截止时间从早到晚模拟安排。不得越过截止时刻、占用已确认事项、扩展可安排时段或重叠排程。无空位时列出未安排事项，由用户决定如何修改。
7. 对确定截止时刻的事项，默认提醒为截止前 **1 天**和 **1 小时**。若创建时某提醒时点已过去，该次提醒不补发；其余未过时点仍生效。
8. 普通日常事项由 AI 提议后经用户确认，才可设置提醒。
9. 修改或删除事项时，关联提醒同步更新或取消。应用启动时检查已保存、未触发的提醒，避免重复通知；已错过的提醒如何呈现由架构设计明确。

## 6. 数据、隐私与安全

1. 日程、提醒和设置保存在本机。第一版不建立 Yuiee 云端账户。
2. 仅在用户发起分析时，将选定图片和文字发送到 OpenAI API；首次使用时明确说明这一点。
3. API Key 不写入仓库、日志或导出文件；安全存储方式在架构设计中确定。
4. 日志不记录截图原文、完整 Key 或完整 API 请求内容。
5. 图片默认只用于识别流程，不长期保存；用户可删除本地事项及相关数据。
6. GPT 回复作为不可信输入处理；经结构化校验和用户最终确认，才可以影响正式日历及提醒。

2. 在模拟阶段、确认阶段、通知阶段分别验证状态一致性；不得出现模拟未确认却已保存的情况。
3. README 给出安装、运行、配置、构建、测试、开机启动与关闭方法。
4. 发布前进行手工端到端验收：从真实截图粘贴到收到提醒，并检查应用重启与 Windows 登录后的行为。
5. 记录需求到实现和测试的对应关系，发布时附已知限制与验收结果。
